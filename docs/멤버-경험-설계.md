# 일반 사용자(임직원) 경험 설계

> [플랫폼 재설계 제안](./플랫폼-재설계-제안.md) §9의 구현 설계.
> 로드맵상 6단계지만, **지금 이 영역이 통째로 비어 있어** 4·5단계보다 먼저 열 가치가 있습니다.

---

## 1. 현재 진단 — 임직원이 들어올 문이 없다

| 확인 항목 | 현황 |
|---|---|
| `/login` | **일반 관리자 / 최고 관리자 2가지뿐** — 임직원 옵션이 없음 |
| `/guest` | 양식 작성 페이지. 사용자 공간이 아님 |
| 내 응답 이력 | ❌ 없음 |
| 내 추세 | ❌ 없음 |
| 포인트 | ❌ 없음 |

응답자는 개인화 링크로 폼에 들어와 제출하면 그걸로 끝입니다.
**자기가 뭘 냈는지 다시 볼 방법조차 없습니다.**

---

## 2. 로그인 진입점

로그인 화면의 역할 토글을 **3분할**합니다.

```
[ 임직원 ]  [ 일반 관리자 ]  [ 최고 관리자 ]
     ↓             ↓                ↓
   /me      /admin/dashboard   /super-admin
```

### 임직원은 로그인 없이도 응답할 수 있어야 합니다

이 점이 헷갈리기 쉬운데, **두 경로는 공존합니다.**

| 경로 | 로그인 | 용도 |
|---|---|---|
| 개인화 링크 `/q/{id}/enter?t=…` | ❌ 불필요 | 응답만 — 응답률을 위해 마찰을 없앤다 |
| 로그인 → `/me` | ✅ 필요 | 이력·추세·포인트 조회 |

응답 세션 쿠키는 **해당 양식 하나**에만 유효하므로, 마이페이지 전체를 열어주지 않습니다.
내 데이터를 통합해서 보려면 정식 로그인이 필요합니다 — 이게 맞는 경계입니다.

> ⚠️ 현재 인증은 쿠키를 그대로 신뢰하는 개발용 브릿지입니다. 마이페이지는 개인 데이터와
> (앞으로) 포인트를 다루므로, **실제 인증(LDAP 또는 자격증명 + 정식 세션) 없이 운영에
> 올리면 안 됩니다.** 지금 구현은 화면·데이터 흐름을 확정하기 위한 것입니다.

---

## 3. 대시보드 위젯

우선순위는 **"지금 내가 해야 할 일"**이 맨 위입니다. 이력은 그 다음입니다.

```
━━ 안녕하세요, 최고관리자 님 ━━━━━━━━━━━━━━━━━━━━

  [⚠ 조치 필요 2]   [응답한 양식 5]   [보유 포인트 —]   [이번 분기 참여 3/4]

━━ ⚠ 지금 응답이 필요합니다 ━━━━━━━━━━━━━━━━━━━━
  보유장비 현황     2026 Q1 · 3/31까지 (D-4)       [응답하기]
  자격증 정보       2026 Q1 · 기한 없음             [응답하기]

━━ 최근 응답 ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
  온보딩 피드백     2026 Q2 · 2026-07-29 · 1회 수정
  만족도 조사       기본 수집 · 2026-07-28  🔒익명 포함

━━ 포인트 ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
  (보상 제도 준비 중 — 적립 시작 시점은 별도 공지됩니다)
```

### 위젯별 데이터 출처

| 위젯 | 출처 | 비고 |
|---|---|---|
| **조치 필요** | `CampaignTarget` 중 `respondedAt=null` + 회차 `OPEN` | ⭐ 가장 중요 — 여러 부서 요청이 한곳에 모인다 |
| 응답한 양식 | `CampaignParticipation` | 양식 단위로 집계 |
| 보유 포인트 | `PointLedger` 합계 | 원장이 비어 있으면 "준비 중" |
| 이번 분기 참여 | 대상 회차 대비 응답 수 | |
| 최근 응답 | `CampaignParticipation` 최신순 | 익명 문항 포함 여부 표시 |

> 💡 **"조치 필요"가 이 화면의 존재 이유입니다.** 지금은 각 부서가 따로 링크를 보내니
> 임직원 입장에서 무엇이 밀렸는지 파악할 방법이 없습니다. 한곳에 모으는 것만으로
> 응답률이 올라갑니다.

## 4. 내 응답 이력

### 목록

응답한 **양식지 단위**로 묶고, 그 안에 회차를 펼칩니다.

```
온보딩 피드백                        2회 참여   최근 2026-07-29
  ├ #2 2026 Q2 정기조사   2026-07-29   1회 수정   [내용 보기]
  └ #1 기본 수집          2026-07-28              [내용 보기]
```

### 상세 — 익명 문항은 본인에게도 보이지 않습니다

```
부서명        이동한팀
입사자 성함    식별응답자
가장 유용했던 세션   🔒 익명으로 저장되어 조회할 수 없습니다
근무 희망지         🔒 익명으로 저장되어 조회할 수 없습니다
```

본인에게 보여주는 것조차 "당신과 연결되어 어딘가에 저장돼 있다"는 뜻이 되어
익명성 주장이 무너집니다. 이 제약은 **응답 시점에 미리 고지**해야 합니다(이미 반영됨).

---

## 5. 나의 추세

반복 수집 양식에서 **내 값이 회차마다 어떻게 바뀌었는지** 보여줍니다.

```
━━ 보유장비 현황 — 나의 변화 ━━━━━━━━━━━━━━━━━━

  항목        #1 기본수집    #2 Q2        변화
  부서명       개발1팀        이동한팀      ✏ 변경됨
  보유 장비    노트북 1       노트북 2      ✏ 변경됨
  근무지       판교           판교          — 동일

  🔒 익명 문항 2개는 추세를 볼 수 없습니다
```

### 설계 판단

- **회차가 2개 이상인 양식만** 추세 대상 — 1회성 양식엔 의미가 없습니다
- **익명 문항은 원천적으로 제외** — 회차 간 연결 자체가 재식별 경로입니다
- **스키마 버전이 다른 구간은 경고** — 5점 척도와 7점 척도를 한 줄로 이으면 없는 추세가 생깁니다
- 수치 필드는 추후 스파크라인, 지금은 값 비교 테이블로 충분합니다

## 6. 포인트 — 지금은 "읽기 전용"으로 엽니다

### 🔴 자동 적립은 켜지 않습니다

로드맵에서 **품질(5단계) → 적립(7단계) → 지급(8단계)** 순서를 강조했고,
그 이유는 *"품질보다 보상을 먼저 열면 공정성을 담보할 수단이 없는 상태에서
어뷰징이 먼저 학습된다"* 였습니다. 그 판단을 여기서 뒤집지 않습니다.

그래서 이번에 만드는 것은:

| 만드는 것 | 만들지 않는 것 |
|---|---|
| `PointLedger` 스키마 (append-only) | 제출 시 자동 적립 |
| 상태 전이(PENDING/APPROVED/PAID/REJECTED) | 정산·지급 화면 |
| 잔액·내역 조회 화면 | 보상 정책 설정 |

원장이 비어 있으면 화면은 **"보상 제도 준비 중"** 을 정직하게 표시합니다.
가짜 숫자를 보여주지 않습니다 — 이 프로젝트에서 목업 API 모달을 걷어냈던 것과 같은 원칙입니다.

### 원장 설계 (§6-1 원칙 유지)

```prisma
model PointLedger {
  id     String @id
  userId String
  /// 부호 있는 증감. 이 값은 절대 수정하지 않는다 — 회수는 반대 부호의 새 행으로.
  delta  Int
  reason String
  status PointStatus   // PENDING → APPROVED → PAID / REJECTED
  /// 적립 근거 스냅샷 — "그때 약속한 규칙"을 남겨야 분쟁에 대응할 수 있다.
  policySnapshot Json?
  campaignId String?
  createdAt DateTime
}
```

잔액은 `SUM(delta) WHERE status='PAID'`로 계산합니다. 잔액 컬럼을 두고 UPDATE 하지 않습니다.

## 7. 화면 구성

```
/me                     대시보드 (위젯)
/me/responses           내 응답 이력
/me/responses/[formId]  양식별 회차 목록 + 상세
/me/trends/[formId]     나의 추세
/me/points              포인트 잔액·내역
```

공통 레이아웃에 좌측 네비게이션을 두되, **관리자 포털과 시각적으로 구분**합니다
(관리자는 짙은 사이드바, 임직원은 밝은 상단 네비) — 같은 사람이 두 역할을 오갈 때
지금 어느 공간에 있는지 헷갈리지 않아야 합니다.

---

## 8. 구현하지 않는 것 (명확히)

| 항목 | 이유 |
|---|---|
| 자동 포인트 적립 | 품질 게이트(5단계)가 없으면 어뷰징을 막을 수 없음 |
| 결과 피드백("내 응답이 이렇게 쓰였습니다") | 제작자가 회차 마감 시 요약을 남기는 기능이 선행되어야 함 |
| 정보주체 권리(열람·정정·삭제 요청) | 정식 인증 도입 후 |
| 수치 필드 스파크라인 | 4단계 history 구조 위에 얹는 편이 정확함 |
