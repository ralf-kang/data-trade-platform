# 워드클라우드 / 연관 키워드 분석 설계

> 상태: **설계 확인 대기** — 구현 전 승인 필요
> 작성 배경: 현재 `/admin/data/[formId]/wordcloud`는 최소 기능만 있고, 메뉴 진입점·범위 설정·
> 연관 키워드 분석이 없다. 아래 3장에 **현재 구현의 결함**을 먼저 정리하고, 벤치마킹을 반영한
> 재설계를 제시한다.

## 1. 요구사항 정리

| # | 요구 | 현재 상태 |
|---|---|---|
| 1 | **메뉴 진입점** | ❌ 없음 (제출 데이터 뷰어 안의 버튼뿐) |
| 2 | **범위 설정** — 전체 양식지 / 특정 양식지 / 특정 컴포넌트 | ❌ 없음 (양식지 1개의 모든 자유서술 문항 고정) |
| 3 | **키워드 뒤에 따라오는 키워드 + 카운트 조건** | ❌ 없음 |
| 4 | 타 사이트 벤치마킹 반영 | ❌ |

벤치마킹 대상: Voyant Tools(Cirrus/Collocates/Links/Contexts/Phrases), AntConc(Collocates/Clusters),
Sketch Engine(Word Sketch, logDice), TagCrowd, WordArt, Wordclouds.com, SurveyMonkey, Qualtrics
Text iQ, TEXTOM·썸트렌드(국내).

## 2. ★ "X 뒤에 오는 키워드"는 사실 세 가지 다른 분석이다

이 구분을 먼저 못 박아야 설계가 흔들리지 않는다.

| 유형 | 정의 | 대표 구현 |
|---|---|---|
| **(A) 후행 인접어** | X 바로 다음 토큰. 순서·인접 보장 | AntConc **Clusters**, Voyant **Phrases** |
| **(B) 윈도우 공기어** | X 좌우 N토큰 이내 등장. 통계 검정으로 "우연 이상"만 추림 | AntConc **Collocates**, Voyant **Links** |
| **(C) 문법관계 공기어** | X의 목적어/수식어 등 문법 역할별 | Sketch Engine **Word Sketch** |

요청하신 "X 뒤에 따라오는 키워드"는 **(A)** 에 가깝지만, **실무적으로 의미 있는 인사이트는
(B)에서 나온다.** 특히 **한국어는 어순이 자유롭고 조사가 격을 표시**하므로 "바로 다음 단어"의
정보량이 영어보다 낮다. → **(B)를 주력, (A)를 보조**로 두고 **둘 다 제공**하는 것을 권한다.
(C)는 한국어 sketch grammar가 필요해 범위 밖.

## 3. ⚠️ 현재 구현의 결함 (재설계 전 정직하게 정리)

지금 배포된 워드클라우드에는 다음 문제가 있다. 기능 추가가 아니라 **수정**이 필요한 항목이다.

### 3-1. 한국어 조사 때문에 단어가 파편화된다 (가장 심각)

현재는 공백 기준으로만 자른다. 그래서 **"교육을 / 교육이 / 교육은 / 교육에"가 전부 다른
단어**로 집계된다. 워드클라우드가 조사별로 쪼개져 사실상 쓸모가 없다.
(실제 f-101 테스트 결과에서도 "속도가", "수단이", "다양했으면" 같은 어절이 그대로 나왔다.)

### 3-2. 빈도를 "총 등장 횟수"로 센다 → 재식별 위험

한 사람이 같은 단어를 10번 쓰면 10으로 집계된다. 이는 두 가지 문제를 낳는다.
- 한 명의 장문 응답이 전체 클라우드를 왜곡한다.
- **k-익명성 게이트를 걸 수가 없다.** 빈도가 "몇 명이 썼는지"를 뜻하지 않기 때문이다.

→ **응답 수(document frequency) 기준으로 바꿔야 한다.**

### 3-3. 희귀어에 k 하한이 없다 → 희귀 단어 1개가 곧 개인 식별자

지금은 1회만 등장한 단어도 그대로 노출된다. 자유서술에서 **1명만 쓴 단어는 사번·이름·
특이 사업명·부서 고유 표현일 가능성이 높다.** 마스킹 계층이 막으려던 것을 워드클라우드가
그대로 흘리는 셈이다.

→ **`min_doc_count ≥ k` 강제**가 필요하다.

### 3-4. 익명 문항 취급

익명 문항은 이미 제외하고 있다(정상). 다만 재설계 시에도 **익명 문항은 KWIC 드릴다운을
원천 차단**해야 한다 — 좌우 문맥이 붙는 순간 응답 전문이 재구성되기 때문이다.

## 4. 화면 설계

### 4-1. 메뉴 진입점

관리자 사이드바 **General Admin**에 `텍스트 분석` 추가 (`/admin/text-analysis`).
기존 제출 데이터 뷰어의 버튼은 "이 양식지로 분석 열기" 바로가기로 유지.

### 4-2. 범위 설정 패널 — **첫 번째 컨트롤** (Qualtrics Text iQ 모델)

```
┌─ 분석 범위 ──────────────────────────────────────────────┐
│ 대상   ( ) 전체 양식지   (•) 특정 양식지   ( ) 직접 선택   │
│                                                          │
│ 양식지 [2024 하반기 고객 만족도 조사        ▾]            │
│ 문항   ☑ 개선 사항 (선택)        [장문형]                 │
│        ☑ 이용 중인 서비스        [단답형]                 │
│        ☐ 고객명                  [단답형] 🔒 개인정보     │
│        ─ 만족도 점수             [숫자] (분석 불가)       │
│                                                          │
│ 회차   [전체 ▾]   기간 [2026-01-01 ~ 2026-07-29]         │
│ 세그먼트 [부서 = 개발팀 ▾]  (다른 문항 응답값 기준 필터)  │
└──────────────────────────────────────────────────────────┘
```

- **3단 범위**: 전체 양식지(교차 분석) / 특정 양식지 / 문항 직접 선택 — 요구사항 2-1 대응
- **텍스트형 컴포넌트만** 체크박스로 노출 (숫자·선택형은 비활성 표기)
- **익명 문항은 배지로 표시**하고 선택 시 제약(드릴다운 불가)을 안내
- 회차·기간·세그먼트 필터 (기존 Campaign 스키마 재사용)

> **전체 양식지 범위의 주의점**: 서로 다른 양식지의 응답을 합치면 k 산정 기준이 흐려진다.
> → **k 게이트는 합친 결과가 아니라 원천 양식지별로 각각 적용**한 뒤 합산한다.

### 4-3. 워드클라우드 탭

```
표시 단어 수  [━━━●━━━] 50        (Voyant Cirrus 기본값)
최소 응답 수  [ 5 ]  ← k와 연동, k 미만으로 못 내림
최소 글자 수  [ 2 ]  ← 한국어 1음절 노이즈 제거
글자 크기 스케일  (•) sqrt  ( ) linear  ( ) log
```

- **스케일 기본값을 `sqrt`로** — 설문 응답은 상위 1~2개 단어가 압도적이라 linear면 나머지가
  안 보인다.
- **불용어 3계층**: 시스템 한국어 기본 / 양식지별 추가 / 이 뷰에서만 임시 제외
  (단어 우클릭 → "제외"). Voyant Edit List + TagCrowd "Don't show these words" 조합
- **White List**(Voyant) — 관심 키워드 N개만 표시. 보고서용으로 유용
- **클라우드 옆에 항상 빈도표 병기** (단어 / 응답 수 / 비율). 그림만으로는 근거가 안 된다

### 4-4. ★ 연관 키워드 탭 — 요구사항 2-2 대응

**뷰 ① 후행어 (인접)** — "X 다음에 오는 단어"

| 후행어 | 동시등장 응답 수 | 전체 빈도 | 비율 |
|---|---|---|---|

구현: `shingle` 토큰 필터(min 2, max 3)로 만든 bigram 서브필드 + `terms` agg에 `"X "` prefix.
**명사 시퀀스 기준**으로 뽑아야 "업무 효율", "교육 만족도" 같은 복합명사가 잡힌다.

**뷰 ② 공기어 (윈도우)** — AntConc Collocates 컬럼 구조를 그대로 차용

```
좌 윈도우 [━●━] 5      우 윈도우 [━●━] 5      최소 공기 빈도 [ 5 ]
정렬  (•) 전형성(logDice)  ( ) 총빈도  ( ) 좌빈도  ( ) 우빈도
```

| 공기어 | 총 빈도 | **좌측 빈도** | **우측 빈도** | 점수 |
|---|---|---|---|---|

→ ★ **좌/우 빈도 분리가 "앞에 오는 말 vs 뒤에 오는 말"을 직관적으로 보여주는 장치**다
(AntConc `Freq(L)`/`Freq(R)`). 요구사항의 "따라 나오는 키워드"가 여기서 정확히 답해진다.

- **윈도우는 문장 경계(마침표·줄바꿈)를 넘지 않게 컷.** 설문 응답은 짧으므로
  "응답 1건 = 1윈도우" 옵션도 함께 제공
- **통계 measure 기본값 = logDice** — Sketch Engine의 판단 근거를 그대로 채택한다:
  **logDice는 코퍼스 크기에 영향받지 않아** 응답 수가 다른 양식지 간·회차 간 점수 비교가
  가능하다. 이 플랫폼은 회차 반복 수집을 하므로 이 성질이 특히 값을 한다.
  MI는 희귀어(오타 포함)를 과대평가하고, MI·t-score는 코퍼스 크기에 흔들린다.
- UI에는 통계 용어를 강요하지 말고 **"빈도순 vs 전형성순" 토글**로 노출
- ES 네이티브로 갈 경우 `significant_terms`의 `jlh`(기본)/`chi_square` 사용.
  **`mutual_information`은 불용어를 끌어올리므로 기본값 금지**, `gnd`는 오타·희귀어를 집으므로
  **반드시 k 게이트와 함께**

**뷰 ③ 네트워크 그래프** — Voyant Links 모델
키워드/공기어 노드 색 구분, 빈도 라벨, 노드 드래그 이동 + 캔버스 밖으로 빼서 제거, 표시 노드 수 슬라이더.

### 4-5. 드릴다운 (KWIC) — 익명 문항 제외

단어 클릭 → `좌측 문맥 | 키워드 | 우측 문맥` 표 (Voyant Contexts 구조).
문맥 폭 슬라이더(기본 좌우 5어절, 최대 20), 행 `[+]` 확장으로 응답 전문.
**Left 컬럼은 오른쪽→왼쪽 방향 정렬** (선행어 패턴 파악용 — KWIC 정렬의 표준 관례).
원문은 **반드시 마스킹 적용본**.

## 5. 한국어 처리 — 3-1 해결 방안

| 방안 | 비용 | 품질 | 판단 |
|---|---|---|---|
| **ES `analysis-nori` 플러그인** | 플러그인 설치 + 재색인 | 상 | ★ **권장.** 이미 ES를 쓰고 있어 스택에 가장 잘 맞고, Python 런타임이 필요 없으며, 색인 시점 처리라 조회는 오히려 빨라진다 |
| KoNLPy / Kiwi | **Python 런타임 별도 필요** | 상 | Next.js 스택에 이질적 |
| soynlp / KR-WordRank (비지도) | 사전 불필요 | 중 | 응답 수가 적으면(수십 건) 통계가 안 잡힘. 설문에는 주력으로 위험, 보조로만 |
| 조사 절단 휴리스틱 | 의존성 0 | 하~중 | 폐쇄망 폴백용 |

**Nori 설정 요점**
- 텍스트 필드에 **multi-field로 `.nori` 서브필드** 추가 (원문 보존 + 분석용 분리)
- **`nori_part_of_speech`의 기본 stoptags에 조사(`J`)·어미(`E`)가 이미 포함**되어 있다.
  워드클라우드용으로는 여기서 더 좁혀 **명사(NNG/NNP) 위주 프리셋**을 별도로 둔다
- **`user_dictionary`** — 기관·부서·제품 고유명사 등록. 관리자 화면에서 편집 가능하게
  (TEXTOM의 "고유명사/복합명사 편집"에 대응하는 자리)
- `decompound_mode`: 복합명사 분해 정책. 워드클라우드에는 `mixed` 또는 `discard`

**폐쇄망 폴백**: Nori 미설치 시 조사 절단 휴리스틱으로 자동 전환하되, **UI에 "간이 분석 모드"
배지**를 띄워 품질 차이를 명시한다. 절단 규칙에는 안전장치 필수 —
**절단 후 2음절 미만이면 절단하지 않음**(`사과`→`사가` 방지), **화이트리스트**(우리/나라/사과/
문의/회의/조사 등 조사로 끝나는 것처럼 보이는 실제 단어).

## 6. 프라이버시 안전장치 (3-2·3-3 해결)

| # | 장치 | 내용 |
|---|---|---|
| W1 | **빈도 = 응답 수(document frequency)** | 토큰 총 등장 횟수가 아니라 "그 단어가 등장한 서로 다른 응답 수". 한 사람의 반복이 클라우드를 왜곡하는 것을 막고, k 게이트를 직접 걸 수 있게 된다 |
| W2 | **`min_doc_count ≥ k`** | k 미만 응답에만 등장하는 단어는 **아예 제외**. 희귀어 1개가 곧 개인 식별자다 |
| W3 | **필터 조합 탐색 공격 차단** | 필터 적용 후 결과 집합이 k 미만이면 전체 차단(`BELOW_ANONYMITY_THRESHOLD`). **부분 결과를 절대 내보내지 않는다** |
| W4 | **마스킹 계층 이후 텍스트를 입력으로** | 원문이 아니라 마스킹된 필드를 분석 (현재 구현도 이미 준수) |
| W5 | **패턴 토큰 정규식 제외** | 숫자열·이메일·전화번호·영문+숫자 혼합 토큰을 토큰 단계에서 기본 제외 |
| W6 | **익명 문항 KWIC 원천 차단** | 빈도표·공기어표까지만 허용. 좌우 문맥이 붙으면 응답이 재구성된다 |
| W7 | **내보내기에도 k 재적용** | CSV로 우회되는 사고 방지 |

## 7. 운영 품질 (P2 — 여유 되면)

- **정제(refine) 워크스페이스** (TEXTOM 모델): 결과 화면에서 바로 **유의어 통합**
  ("만족/만족도/만족함" → 대표어), **복합명사 등록**, 불용어 추가를 표에서 클릭 한 번으로.
  **원본을 건드리지 않고 매핑 사전만 갱신**해 되돌릴 수 있게. 국내 실무자가 가장 강하게
  기대하는 UI다
- **규칙 기반 태깅** (SurveyMonkey): 키워드/구 규칙으로 태그 정의 → 기존 응답에 소급 +
  신규 응답에 자동 적용. 한국어 감성 모델 확보 비용이 크므로 1차로는 이쪽이 현실적
- **내보내기**: PNG + SVG(이미지), CSV(빈도표·공기어표·n-gram표). 보고서에 실제 쓰이는 건 CSV
- **회차 간 비교** — ★ 이 플랫폼 고유 강점.
  썸트렌드의 "연관어 순위 변화 추이" + Sketch Engine "Word Sketch Difference"를 결합:
  **1회차 vs 2회차 대조, 신규 등장/급상승/소멸 키워드 표**.
  logDice가 코퍼스 크기 독립이라는 성질이 여기서 값을 한다.
  단, **익명 문항은 회차 간 개인 추세가 원천 불가**하므로 집단 수준 집계 비교만 허용
- **캐시**: 폼/문항/필터 조합별 결과를 캐시하되 **키에 `schemaVersion` 포함** →
  폼 필드 변경 시 자동 무효화 (`X-Form-Schema-Version` 이미 존재하므로 재활용)

## 8. 단계 제안

| 단계 | 범위 |
|---|---|
| **P0** (필수 수정) | 메뉴 진입점 · 범위 설정 패널 · **Nori 도입** · **빈도를 응답 수 기준으로** · **k 게이트** · 표시 단어 수/최소 빈도/최소 글자 수 · 불용어 3계층 · sqrt 스케일 · 빈도표 병기 |
| **P1** (핵심 요구) | **연관 키워드 탭 3뷰**(후행어 / 좌우 분리 공기어 / 네트워크) · logDice · KWIC 드릴다운 |
| **P2** (운영 품질) | 정제 워크스페이스 · 태깅 · 내보내기 · 회차 간 비교 · 캐시 |

## 9. 확인이 필요한 결정 사항

1. **Nori 플러그인 설치 가능 여부** — 운영 ES에 플러그인을 넣을 수 있는 환경인지.
   불가하면 조사 절단 휴리스틱으로 가야 하고 품질이 눈에 띄게 낮아진다
2. **k 임계값** — 온톨로지 설계서와 동일한 값을 쓸지 (기본 5 제안)
3. **"전체 양식지" 범위를 P0에 넣을지** — 교차 분석은 k 산정이 복잡해지므로
   P0는 특정 양식지·문항 선택까지만 하고 전체 범위는 P1로 미루는 것도 가능
4. **P0 범위 확정** — 현재 구현의 결함(3장) 수정 + 범위 설정까지를 1차로 끊는 것이 맞는지
