# 폼 제너레이터 (Web Report Editor)

이 프로젝트는 기관/기업 내에서 복잡한 양식(설문, 동의서, 서명, 파일 업로드 등 23종의 컴포넌트)을 동적으로 생성하고, 외부 사용자에게 URL/QR/API 형태로 배포하여 데이터를 수집하는 **지능형 동적 폼 빌더 플랫폼**입니다.

## 🚀 주요 기능 (Key Features)

### 1. 최고 관리자 (Super Admin) 워크스페이스
- **기본 접속 계정**: `admin@example.com` (시드 계정). 로그인은 아직 실제 인증이 아니라 **브라우저에서 값만 비교하는 목업**이며, 개발용 기본값은 `src/app/login/page.tsx` 상단에 있습니다. 아래 "알려진 한계" 참고
- **조직 및 하위 관리자 제어 (`/super-admin/users`)**
  - 하위 관리자 초대 (이메일 발송)
  - 등록된 하위 관리자 리스트 조회
  - 단일 팝업 모달을 통한 사용자 권한 승급(SUPER_ADMIN 전환), 비밀번호 초기화, 계정 정지 및 영구 삭제 처리 기능
- **시스템 환경 설정 (`/super-admin/settings`)**
  - SMTP 메일 서버 연동 (초대 메일, 비밀번호 찾기 등 발송용)
  - Claude API OAuth 2.0 연동 (AI 자동 양식 생성용 자격 증명)
  - **외부 연결 목록 (방화벽 허용 목록)**: 이 시스템이 외부로 요청을 보내는 모든 목적지(주소 검색·지오코딩·지도 타일·LDAP·SMTP)를 한 표에 모아 모드(내장/외부/사용안함)·호스트·포트와 함께 표시하고, 항목별 연결 확인 버튼 제공. **화면에 보이는 값이 곧 실제 호출 대상**이 되도록 목적지를 코드가 아닌 DB(`ExternalEndpointConfig`)에 두어, 폐쇄망 반입 시 이 표에서 그대로 방화벽 허용 목록을 뽑을 수 있음
- **전체 행동 감사 (Audit Logs)**
  - 플랫폼 내에서 이루어지는 모든 사용자의 행동 이력 조회

### 2. 일반 관리자 (Admin) 워크스페이스
- **대시보드 메인 (`/admin/dashboard`)**
  - 생성한 폼 개수, 누적 제출 수, 일일 방문자 트래픽 시각화 차트
- **내 양식 관리 및 폼 빌더 (`/admin/templates`, `/admin/builder`)**
  - 드래그 앤 드롭 기반의 동적 폼 생성 (단답형, 장문형, 서명, 지도 등 23개 컴포넌트 지원)
  - 기존 양식을 템플릿화 하거나 부분 복사(Partial Clone) 가능
  - 모바일/PC 반응형 실시간 프리뷰 기능 지원
- **배포 URL 및 접속 관리 (`/admin/templates/urls`)**
  - 양식별 배포 URL 생성 및 QR 코드 자동 발급
  - **대용량 트래픽 대응용 다중 API 자동 발급 (Load Balanced Endpoints)** 기능 제공
  - 클릭 한 번으로 양식 제출 마감(Closed) 제어
- **제출 데이터 뷰어 (`/admin/data/[formId]`)**
  - 수집된 데이터의 실시간 테이블 뷰
  - 이상치 자동 감지 및 관리자 수동 재가공(수정) 에디터 내장

- **데이터 품질 대시보드 (`/admin/data/[formId]/quality`)** — `docs/데이터품질-검증구간-설계.md` §5의 7개 우선순위 항목 중 6개가 구현됨(잔여 1건은 이 문서 하단 로드맵 참고)
  - 문항별 결측률 자동 집계, 숫자 문항의 사분위수(IQR) 기반 이상치 탐지
  - **추세선**: 주간 응답량 + 숫자 문항 평균값을 막대그래프로 시각화(외부 차트 라이브러리 없이 SVG/CSS로 렌더링)
  - **기능 분석**: 문항별 응답 분포(숫자 문항은 평균·최소·최대·표준편차, 선택형 문항은 옵션별 응답 비율)
  - **주제별 응답 그룹**: 자유서술형 문항의 응답을 워드클라우드와 같은 안전장치(마스킹 인지 + k=5 게이트)로 주제어 그룹핑해 표시
  - **대표성 경고**: 전체 응답 수 또는 특정 문항 표본이 너무 적으면(기본 10건 미만) 통계가 실제 경향을 대표하지 못할 수 있다는 경고 배너
  - 자유서술형 문항은 마스킹 보호 대상이라 이상치 판정에서 제외(내용 노출 없이 결측 여부만 확인)
  - 응답자를 특정할 수 있는(식별) 제출 건에 한해 "수정 요청" 발송 → 응답자가 재제출(수정)하면 자동으로 처리 완료 처리
- **워드클라우드 (`/admin/wordcloud`)**
  - 본인이 제작한 양식지(전체 또는 특정 문항)의 자유서술형 응답에서 자주 등장한 단어를 시각화
  - 한국어 형태소 분석은 Elasticsearch `analysis-nori` 플러그인, 렌더링은 `@isoterik/react-word-cloud` 사용
  - 빈도는 "등장 횟수"가 아니라 "등장한 서로 다른 응답 수"로 집계하고, 응답 5건 미만인 단어는 표시하지 않음(k-익명성 보호)
  - **개인정보취급자 k=5 우회 모드**: 인증(`AUTHENTICATED`) 양식지이고 제작자가 개인정보 취급자 승인을 받은 경우에 한해, 매 요청 명시적 동의 + 확인 대화상자를 거쳐 k=5 미만 단어까지 조회 가능(모든 우회 조회는 감사 로그에 기록)
- **주소 분포 지도 (`/admin/data/[formId]/map`)**
  - 수집된 주소를 지역 단위로 집계해 지도에 표시. 렌더링은 `leaflet` + `react-leaflet`, 클러스터링은 `react-leaflet-cluster`(`Leaflet.markercluster` 래퍼), 배경 타일은 설정에서 주입(기본 OpenStreetMap)
  - **클러스터링을 프라이버시 장치로 사용**: 지도에 올라가는 점 자체가 이미 k 게이트를 통과한 지역 집계 단위이므로, 어떤 확대 수준에서도 개별 응답 위치가 표시되지 않음. 클러스터 라이브러리는 "이미 안전한 점들"을 보기 좋게 묶는 데만 쓰고, 개별 좌표를 클라이언트로 내보내지 않음(화면에 클러스터만 보여도 네트워크 응답에 원본이 남기 때문)
  - 응답 수가 최소 기준 미만인 지역은 표시하지 않고, **몇 곳이 가려졌는지를 배너로 알림** — "데이터가 없는 것"과 "가려진 것"을 구분하기 위함
  - 문항별로 제작자가 「지도 분포 분석 대상으로 사용」을 **명시적으로 켜야만** 대상이 됨(기본 꺼짐). 마스킹 대상 양식지·익명 문항·개인식별자 문항은 원천 제외되며, 모든 조회는 감사 로그에 기록됨
  - 지오코딩 미설정 시에는 시·도 단위 핀 + 시·군·구 표로 동작(법정동코드만으로 계산되므로 키 없이도 정상 동작)
- **사용 매뉴얼 (`/admin/manual`, `/me/manual`)**
  - 관리자용·응답자용 매뉴얼을 화면 안에 내장. 기능 설명뿐 아니라 **"왜 그렇게 동작하는지"**를 함께 설명함 — 예컨대 지도에서 일부 지역이 안 보이는 것은 데이터가 없어서가 아니라 k-익명성 때문이라는 식
  - 본문 전문 검색, 그룹별 목차, 각 기능 화면의 **도움말 버튼이 해당 항목으로 바로 이동**(`?s=<섹션id>`)
- **양식 빌더 — 비슷한 양식지 추천**
  - 새 양식을 작성할 때 제목을 입력하면 Elasticsearch `more_like_this`로 제목·문항 라벨이 비슷한 기존(확정된) 양식지를 찾아 "이런 양식이 이미 있습니다" 배너로 안내, 중복 제작을 줄임

### 3. 최고 관리자 전용 — 데이터 구조 · 관계
- **데이터 구조 관계도 (`/super-admin/data-map`)**
  - 이 시스템 자체의 저장 구조를 시각화하는 내부 유틸리티. **정형(PostgreSQL)과 비정형(Elasticsearch)을 함께** 표시하며, 두 저장소는 색·테두리(흰 실선 vs 주황 점선)로 구분됨
  - 연결선도 성질을 구분함: 같은 저장소 안의 **외래키(FK)**는 실선, 저장소가 달라 `formId` 값만 일치하는 **공유 키**는 주황 점선 — 후자는 참조 무결성이 없어 양식지가 지워져도 ES 문서가 고아로 남을 수 있기 때문에 같게 그리면 없는 보장을 있는 것처럼 오해하게 됨
  - **양식지 → 컬럼 · 키 · 값 구성** 섹션: 실제 양식지 하나를 예시로, 각 문항이 ES 문서의 어떤 키(`data.{필드id}`)에 저장되는지와 동적 매핑이 붙이는 서브필드(`.keyword`/`.nori`)를 표로 보여주고, 그 옆에 실제 문서 모양(JSON)을 나란히 배치 — `data` 바깥은 모든 양식지 공통 고정 필드, 안쪽만 양식지마다 달라진다는 점을 드러냄 (값은 전부 자리표시자이며 실제 응답값은 노출하지 않음)
- **양식지 관계 캔버스 (`/super-admin/form-links`)**
  - 서로 다른 양식지가 같은 값(사번·전화번호 등)을 공유하는지 사용자가 직접 테스트하고 관계로 선언하는 화면
  - 양식지를 카드로 캔버스에 올리고 문항 두 개를 순서대로 클릭하면 연결 테스트가 즉시 실행되어 매치율 배지로 표시
  - **재식별 위험 방지 안전장치**: 익명 문항은 대상에서 원천 배제, 응답 5건 미만이면 어떤 수치도 표시하지 않음, 마스킹 대상 양식지는 미리보기 자체를 차단, 개인식별자로 태그된 문항은 값을 블러 처리, 모든 테스트 시도(저장 여부 무관)가 감사 로그에 기록됨
  - 최초 진입 시 재식별 위험 안내 모달에 동의해야 하며, 이 기능은 슈퍼관리자만 사용할 수 있음

### 4. 사용자(User) 응답 화면
- **외부 응답 페이지 (`/q/[formId]`)**
  - 배포된 URL/QR을 통해 일반 사용자가 응답을 제출할 수 있는 반응형 렌더링 화면
  - **f-999 테스트 폼**: 23종의 모든 컴포넌트가 렌더링되는 종합 테스트 화면 확인 가능
  - 응답자 신원 요구 수준(`identityMode`): 익명 / 식별(개인화 링크) / 인증(로그인) / 혼합 — 4가지 모두 실제 동작으로 구현됨(아래 "개인정보 보호 계층" 참고)
  - **LDAP 자동 채움 + 읽기 전용**: 텍스트 필드를 LDAP 속성(이름/사번/부서/직급/이메일)에 바인딩하면, LDAP 계정으로 확인된 응답자는 해당 값이 자동으로 채워지고 읽기 전용으로 바뀜(로컬 계정은 직접 입력)
  - **개인정보 동의서 컴포넌트**: 관리자가 「개인정보 보호법」 제15·17조 법정 필수 고지 항목(수집 목적·항목·보유기간, 선택적 제3자 제공)을 구조화된 값으로 입력하면, 응답자에게 보여줄 동의 문구가 자동으로 조립됨(빌더 미리보기와 실제 응답 화면이 같은 함수를 공유해 문구가 어긋나지 않음)
  - **주소 검색 컴포넌트(`map-address`)**: 키워드로 주소를 검색해 고르면 우편번호·도로명·법정동코드가 자동 입력되고 읽기 전용이 됨(상세주소만 직접 입력). 사람이 타이핑하지 않으므로 오타·표기 흔들림("서울시" vs "서울특별시")이 원천 차단되어 지역 집계가 깨지지 않음. 검색 UI는 `react-daum-postcode`(카카오 우편번호 서비스, API 키 불필요)
  - **값 사전 제안**: 텍스트 필드 입력 중, 같은 문항에 과거 들어온 값 중 비슷한 것을 빈도순으로 제안(ES `prefix`+`fuzzy` 쿼리, 별도 저장소 없이 실시간 집계) — 신원이 확인된 응답자에게는 같은 부서 동료들의 답변도 별도 섹션으로 함께 제안(반드시 선택해야 하며 자동 채움 없음, 부서 인원 5명 미만이면 표시 안 함)

### 5. 임직원(Member) 마이페이지 (`/me`)
- **홈**: 조치 필요(응답 대기) 항목, 내 응답 이력, 보유 포인트 요약
- **내 응답 (`/me/responses`)**: 내가 제출한 응답 이력 + 회차별 추세(`/me/trends/[formId]`)
- **수정 요청 (`/me/corrections`)**: 관리자가 결측치·이상치를 발견해 보낸 수정 요청 목록 — 확인 후 원래 양식지로 이동해 재제출하면 자동 처리 완료
- **포인트 (`/me/points`)**: 응답 보상 포인트 원장(append-only) 조회. 노출 범위는 `SystemConfig.rewardVisibility`(HIDDEN/ADMIN_ONLY/ALL_MEMBERS)로 슈퍼관리자가 제어하며, API·화면 양쪽에 동일한 게이트(`canSeeRewards()`)가 적용됨
- **제작 자격 (`/me/author-authorization`)**: 개인정보 취급자(양식 제작 자격) 신청 — 아래 "개인정보 보호 계층" 참고

### 6. 개인정보 보호 계층 — 여러 방어선이 함께 동작
LDAP `defaultRole`은 항상 `MEMBER`이며, 양식을 만들 수 있는 자격(개인정보 취급자)은 자동 부여되지 않고 반드시 신청 → 슈퍼관리자 승인을 거칩니다.

| 방어선 | 내용 |
|---|---|
| **자격 심사** (`AuthorAuthorization`) | 목적·수집예정항목을 적어 신청 → 서약·교육 이수 확인 → 승인. 교육 유효기간(기본 12개월) 만료 시 자동 `SUSPENDED`(신규 생성·확정 차단, 기존 데이터 조회는 유지). 재승인 주기 기본 24개월. `/super-admin/author-authorizations`에서 명부 관리 |
| **동의서 컴포넌트 게이트** | `privacy-consent` 컴포넌트는 무자격자에게 팔레트에서 잠기고, 신원을 요구하는 양식(`identityMode` ≠ ANONYMOUS)에 동의서 문항이 없으면 확정(발행)이 차단됨 |
| **조합 위험 경고** | 빌더가 준식별자 조합(예: 부서+성별+숫자 문항 2개 이상)을 감지하면 저장 전 경고, 진행 사유를 기록(`privacyWarningAck`). 응답 축적 후에는 실제 k=1 여부를 재진단(`/api/forms/[formId]/privacy-risk`) |
| **마스킹 계층** (핵심 방어선) | `FormRegistry.authorHadPrivacyAuth`는 **제작 시점에 고정**되고 사후 자격 취득으로 소급 해제되지 않음. 무자격 상태로 만든 양식은 자유서술형 문항 + k=1 레코드가 조회 화면·CSV 추출·외부 v1 API **세 경로 모두**에서 서비스 계층에 마스킹됨(화면만 가리면 API로 우회되므로). 예외는 슈퍼관리자가 사유를 남기고 명시적으로 해제해야만 적용. 값 사전 제안·워드클라우드·품질 대시보드 주제별 그룹도 모두 같은 원칙(마스킹 대상 폼은 자유서술 원문 집계 자체를 하지 않음)을 공유 |
| **`identityMode` 강제** | 익명(`ANONYMOUS`) 양식지는 개인화 응답 링크 발급 자체가 서버에서 차단됨(링크를 받는 순간 익명이 아니게 되므로). 응답자 신원 해석(`resolveRespondent`)은 양식이 `ANONYMOUS`면 어떤 로그인 세션·토큰 쿠키가 있어도 무조건 익명으로 처리 — 관리자 포털에 로그인한 채로 같은 브라우저에서 익명 설문에 접속해도 신원이 새지 않음 |
| **배포 범위 통제** | `Campaign.distributionScope`(부서/전사) + 전사 배포 시 `FormApprovalRequest`로 슈퍼관리자 승인 필요, 응답자 1인당 주간 발송 한도(`SystemConfig.maxWeeklyInvitesPerUser`) |

## 🏗️ 아키텍처 (Architecture)

### 정형 / 비정형 데이터베이스 분리
| 구분 | 저장소 | 대상 데이터 | 이유 |
|---|---|---|---|
| 정형 | PostgreSQL (`prisma/schema.prisma`) | 관리자 계정, 폼 운영 메타데이터(`FormRegistry`: 상태/소유자/URL/조회·제출 카운터), 감사 로그, 공유 요청 | 스키마가 고정적이고 관계(소유자, 요청자 등) 조회가 중요한 데이터 |
| 비정형 | Elasticsearch (`src/lib/elasticsearch.ts`) | 폼 필드 구성(`webreport-form-templates`), 제출 데이터(`webreport-submissions`) | 폼마다 필드 구성이 다르고 계속 확장되며, 제출 데이터의 컬럼 수/타입이 폼 필드에 종속적으로 늘어남 |

두 저장소는 `FormRegistry.id` (예: `f-101`)를 공용 키로 공유해 서로 조인된다. 실제 CRUD는 `src/lib/services/*` 서비스 계층 → `src/app/api/**/route.ts` Route Handler를 거쳐 프론트엔드에 `fetch`로 노출된다.

### 3-tier Docker 구성
```
[nginx: web]  →  [Next.js: WAS]  →  [PostgreSQL: 정형 DB]
   (80 포트)      (Route Handlers)    [Elasticsearch: 비정형 DB]
```
- `Dockerfile`: 멀티스테이지 빌드(`deps → builder → migrator/runner`). `next.config.ts`의 `output: "standalone"`로 런타임 이미지를 경량화.
- `docker-compose.yml`: `web`(nginx 리버스 프록시) · `app`(WAS) · `postgres` · `elasticsearch` · `migrate`(1회성 Prisma 마이그레이션) 서비스로 분리.
- `docker/nginx/nginx.conf`: 외부에 노출되는 유일한 진입점. `/_next/static/`은 장기 캐시, 나머지는 WAS로 프록시.

### 로컬 실행
```bash
cp .env.example .env
docker compose up --build
# 최초 1회, 데모 데이터 적재 (mock으로 있던 데이터를 Postgres/Elasticsearch에 시드)
docker compose run --rm seed
```
브라우저에서 `http://localhost` 접속.

Docker 없이 로컬 Postgres/Elasticsearch를 직접 띄워 개발하려면:
```bash

npm run db:seed         # 데모 데이터 적재
```

## 🔌 외부 연동 API (v1) — 대량 조회/입력

외부 시스템(ERP·그룹웨어·타 서비스)이 양식지 단위로 제출 데이터를 대량 송수신할 수 있는 공개 API입니다.
관리자 화면의 **배포 URL 관리 → DB 아이콘** 또는 **빌더 → "API 연동"** 버튼으로 각 양식지의 API 콘솔(`/admin/forms/{id}/api`)에 진입해 키 발급·계약 확인·테스트를 한 곳에서 할 수 있습니다.

### 양식지 라이프사이클과 계약(Contract)
| 상태 | 의미 | 외부 API |
|---|---|---|
| `DRAFT` (초안) | 설계 진행 중 — 필드 구성이 계속 바뀔 수 있음 | 조회만 가능, **입력 차단** (`409 FORM_NOT_PUBLISHED`) |
| `PUBLISHED` (확정) | 필드 구성이 연동 계약으로 고정됨 | 조회+입력 가능 |

- 확정 후 필드를 수정하면 **schemaVersion이 자동 증가**하며, 모든 v1 응답의 `X-Form-Schema-Version` 헤더로 노출됩니다. 연동 측은 이 값이 바뀌면 매핑을 점검해야 합니다.
- 확정/초안 전환은 API 콘솔 상단 버튼(내부적으로 `POST /api/forms/{id}/publish`)으로 합니다.

### 인증 — 양식지 단위 API 키
- `Authorization: Bearer wre_...` 헤더. 키는 특정 양식지에 묶이며 다른 양식지에는 사용 불가.
- 권한: `READ` / `WRITE` / `READ_WRITE`, 키별 분당 요청 한도·만료일 설정, 즉시 폐기 가능.
- 원문 키는 발급 시 1회만 표시되고 서버에는 SHA-256 해시만 저장됩니다. 발급/폐기는 감사 로그에 기록됩니다.

### 엔드포인트
```
GET  /api/v1/forms/{formId}/schema              # 연동 계약 조회 (필드 id/타입/필수/제약)
GET  /api/v1/forms/{formId}/submissions         # 대량 조회 — 커서 페이지네이션
     ?pageSize=100 (최대 1000)
     ?since=2026-07-01T00:00:00Z                #   증분 동기화 (이 시각 이후 신규분만)
     ?cursor=...                                #   이전 응답의 nextCursor로 이어받기
POST /api/v1/forms/{formId}/submissions         # 단건 입력 (strict 검증)
POST /api/v1/forms/{formId}/submissions/bulk    # 대량 입력 (최대 1,000행/요청)
```

### 대량 입력의 신뢰성 장치
- **행별 결과**: 응답이 각 행의 `accepted / rejected / duplicate` 상태와 오류 사유를 담으므로, 거부된 행만 고쳐 재전송하면 됩니다. (HTTP 200 전량수용 / **207** 부분수용 / 422 전량거부)
- **멱등성**: 행에 `externalId`(외부 시스템 고유키)를 넣으면 같은 배치를 재전송해도 중복 적재되지 않습니다 — 타임아웃 후 재시도가 안전해집니다.
- **모드 선택**: `lenient`(기본, 유효한 행만 적재) / `strict`(한 건이라도 오류면 전량 거부 — 정산성 데이터용).
- **비정형 유연성**: 폼에 정의되지 않은 여분 키도 버리지 않고 Elasticsearch에 그대로 적재하고 `unknownFields`로 보고합니다. 연동 측이 필드를 먼저 보내는 과도기에도 데이터가 유실되지 않습니다.
- **검증**: 필수값·정규식·숫자형·선택지(options) 검증을 서버에서 수행하고, 거부 발생 시 양식지 소유자에게 인앱 알림을 보냅니다.

### 사용 예시
```bash
# 1) 계약 확인
curl -H "Authorization: Bearer $API_KEY" https://host/api/v1/forms/f-101/schema

# 2) 전체 데이터 동기화 (nextCursor가 null이 될 때까지 반복)
curl -H "Authorization: Bearer $API_KEY" "https://host/api/v1/forms/f-101/submissions?pageSize=500"

# 3) 대량 입력 (재전송 안전)
curl -X POST -H "Authorization: Bearer $API_KEY" -H "Content-Type: application/json" \
  https://host/api/v1/forms/f-101/submissions/bulk \
  -d '{"mode":"lenient","rows":[{"externalId":"ERP-001","data":{"f101-1":"홍길동","f101-2":"010-1234-5678"}}]}'
```

| 조항 | 요지 | 구현 |
|---|---|---|
| 제91~92조 (보호 대상) | 데이터베이스는 보호 대상, 컴퓨터프로그램 자체는 제외 | 폼 필드/제출 데이터(콘텐츠)만 보호 대상으로 취급하고, 이를 다루는 코드는 별개로 취급 |
| 제93조 (제작자의 권리) | 무단 복제·배포·전송 금지, 반복적·체계적 상당 부분 추출도 금지 | ① 모든 관리자 API에 인증 요구(`src/lib/auth.ts requireAdmin`) ② 목록 조회 API 요청 빈도 제한(`src/lib/rateLimit.ts`, 분당 120회) ③ 서버가 단일 응답으로 내려줄 수 있는 최대 건수 상한(`MAX_PAGE_SIZE=200`, `src/lib/elasticsearch.ts`) ④ 대량 추출(CSV) 전용 엔드포인트 분리 + 더 엄격한 속도 제한(5분당 5회) + 전량 상한(5,000건) — `src/app/api/forms/[formId]/submissions/export/route.ts` ⑤ `robots.txt`로 관리자/API 경로 크롤링 명시적 금지 |
| 제95조 (보호기간) | 제작완료일로부터 5년, 상당한 투자 갱신 시 그 부분은 갱신일로부터 재기산 | `DatabaseRegistration`/`DatabaseUpdateLog` 모델(정형, Postgres)이 제작완료일·갱신이력을 구조화 기록. 보호기간 만료일은 `src/lib/services/databaseRightsService.ts`에서 최근 갱신일 + 5년으로 자동 계산 |
| 명시적 고지 | 권리자·보호 범위를 이용자에게 공지 | `/legal/database-rights` 공개 페이지(로그인 화면·관리자 사이드바에서 링크) + `GET /api/database-registration` 공개 API |
| 감사·추적 | 침해 발생 시 소명 근거 확보 | 모든 대량 추출은 `AuditLog`에 `DATA_EXPORT` 액션으로 기록(요청자, 건수, 절단 여부 포함) |

**알려진 한계**: 레이트 리미터는 현재 단일 프로세스 메모리 기반이라, WAS를 다중 레플리카로
수평 확장하면 인스턴스별로 한도가 분리되어 우회 가능합니다. 운영 확장 시 Redis 등
공유 저장소 기반 리미터로 교체가 필요합니다.

## 🔐 권한 체계 (RBAC)

| 기능 | 일반 관리자(ADMIN) | 슈퍼관리자(SUPER_ADMIN) |
|---|---|---|
| 양식지 생성 | ✅ (본인 소유) | ✅ |
| 양식지 편집/삭제/기간설정 | 본인 소유만 | 전체 |
| 제출 데이터 조회/수정 | **본인 소유 + 공유 승인받은 것만** | 전체 |
| 제출 데이터 CSV 대량 추출 | 조회 권한 + 슈퍼관리자가 허용한 경우만 | ✅ (항상) |
| 양식지 소유권 이전 | ❌ | ✅ |
| 관리자 계정 속성 수정(이름/이메일/소속) | ❌ | ✅ |
| 관리자 승격/강등 (ADMIN ↔ SUPER_ADMIN) | ❌ | ✅ |
| 관리자 계정 정지(제재)/삭제 | ❌ | ✅ (삭제 시 소유 양식지 위임 강제) |
| 관리자별 대량 추출 허용/제한 | ❌ | ✅ |
| 양식지 생성·확정 (개인정보 취급자 자격 필요) | 승인된 경우만(`AuthorAuthorization`) | ✅ |
| 데이터 구조 관계도 / 양식지 관계 캔버스 | ❌ | ✅ (슈퍼관리자 전용 기능) |
| 보상(포인트) 화면 노출 범위 설정 | ❌ | ✅ (`SystemConfig.rewardVisibility`) |

- **제출 데이터 접근 판정**: `canAccessFormData()` (`src/lib/services/formService.ts`) — 소유자 본인, 승인된 공유(`ShareRequest.status = APPROVED`), 슈퍼관리자만 통과. 목록/상세/수정/추출 모든 엔드포인트에서 재검증됩니다.
- **공유 권한 가시성**: 내가 받은 권한은 `/admin/data`(통합 조회) 카드의 `내 양식`/`공유받음`/`조회 권한 없음` 배지로, 내가 남에게 준 권한은 `/admin/templates` 하단 "내가 부여한 제출 데이터 조회 권한" 목록으로 확인합니다.
- **계정 삭제 시 소유권 처리**: 삭제 API는 `reassignOwnerId`를 필수로 요구해, 소유 양식지를 다른 관리자에게 위임하거나 슈퍼관리자 자신에게 귀속시킨 뒤에만 삭제됩니다 (임자 없는 양식지 방지).
- **제출 시점 이상 감지**: 공개 폼 제출 시 필수 미입력·정규식 불일치·숫자 형식 오류를 감지해 감사 로그(`DATA_ANOMALY`)와 소유자 인앱 알림(사이드바 종 아이콘)으로 보고하며, 관리자는 데이터 뷰어에서 직접 수정할 수 있습니다.
- **적재 후 배치 진단**: `/admin/data/[formId]/quality`에서 이미 쌓인 데이터 전체를 대상으로 결측치·이상치를 다시 진단하고, 응답자에게 수정 요청을 보낼 수 있습니다(위 "결측치·이상치 조회" 참고) — 제출 시점 검증과는 별개의, 사후 발견-조치 경로입니다.

## ⚠️ 알려진 한계 (Known Limitations)
- **인증**: 로그인은 여전히 `adminRole`/`adminEmail` 쿠키 기반의 임시 구현입니다(`src/lib/auth.ts` 참고). 운영 전환 전 비밀번호 해시 검증 + 정식 세션(JWT/DB 세션) 기반 인증으로 교체가 필요합니다. 현재는 쿠키만으로 신원이 결정되므로 **권한 체계 자체가 최종 방어선이 될 수 없습니다.**
- **레이트 리미터**: 인메모리 방식이라 WAS를 다중 레플리카로 확장하면 인스턴스별로 한도가 분리됩니다. Redis 등 공유 저장소 기반으로 교체 필요.
- **SMTP / Claude OAuth 설정**: `/super-admin/settings`의 SMTP·OAuth 입력값은 아직 저장되지 않는 목업입니다 (같은 화면의 "운영 서버 공개 기본 URL"만 실제 DB에 저장/적용됩니다).
- **데이터 거래 · B2B 통계(CRM) · 테넌트**: **전혀 구현되어 있지 않습니다.** `/super-admin`의 "데이터 거래 및 B2B 통계 (CRM)" 섹션은 하드코딩된 카드 2개(`영업본부`/`인사팀`)와 **클릭해도 아무 동작하지 않는 버튼 3개**로 이루어진 정적 화면이며, 뒷단에 API·서비스·Prisma 모델이 하나도 없습니다. 거기 쓰인 "테넌트"도 실체가 없는 라벨입니다 — 스키마에 테넌트 개념 자체가 없고, 부서 정보는 `User.department` 문자열로만 존재합니다. 설계는 `docs/테넌트-데이터거래-설계.md`에 정리했고 구현은 착수 전입니다.
- **지오코딩(주소 → 좌표)**: 미설정 상태입니다. 이 때문에 지도 분포는 **시·도 단위까지만** 핀으로 표시되고, 시·군·구 단위는 표로만 제공됩니다. 슈퍼관리자 설정의 「외부 연결」에서 지오코딩 엔드포인트를 설정하면 더 세밀한 핀이 열립니다. 미설정은 오류가 아니라 정상 동작으로 취급합니다.
- **AI 자동 생성기**: `AiAutoGenerator` 컴포넌트는 여전히 목업 응답을 반환합니다(코드 내 TODO 참고).
- **외부 연계 API 발급 모달**: 표시되는 엔드포인트/API Key는 아직 실제 발급되지 않는 예시 값입니다.
- **양식지 관계 캔버스**: 관계 저장(`FormLink`)까지는 되지만, 저장된 관계를 타고 레코드 단위로 hop-by-hop 탐색하는 트리 뷰는 2단계로 미뤄둔 상태입니다(`docs/양식지-관계-온톨로지-설계.md` §2-4).
- **워드클라우드**: 연관 키워드(공기어) 분석 탭은 아직 없고, 단어 빈도 집계까지만 구현되어 있습니다(`docs/워드클라우드-설계.md` P1).

## 🚀 향후 고도화 목표 (Future Roadmap)
- **인증 고도화**: 비밀번호 해시 + 정식 세션 기반 인증, 관리자 초대(SMTP) 실제 연동.
- **AI 폼 자동 생성 고도화**: Claude API를 연동하여 HWPX, Word, Excel 파일을 업로드 시 즉각적으로 Web Form UI로 변환하는 AI Agent 도입.

> ✅ **데이터 품질 검증 §5 우선순위 7개 항목 중 6개 구현 완료**되었습니다: LDAP 자동 채움, Prefill(이력 기반 사전 채움), 값 사전 제안, 품질 대시보드+정정 요청, 대표성 경고, 군집 기반 제안(비슷한 양식지 추천 · 부서 코호트 제안 · 주제별 응답 그룹). 순위2(의미 타입 확장)만 위 로드맵 항목으로 남아 있습니다. 자세한 내용은 위 각 기능 설명과 `docs/데이터품질-검증구간-설계.md`를 참고하세요.
